# Формат заметки

Заметка — `notes/YYYY-MM-DD-slug.md`. Метаданные — frontmatter в плоском подмножестве YAML:
одна пара `ключ: значение` на строку, скаляры и списки в одну строку (`[a, b]`), без вложенности.
Значение с `:`, `#`, кавычками или ведущими цифрами — в двойных кавычках (`"Git 2.53"`, `"1:30"`).
`yaml.safe_load` читает его так же. Свои ключи добавлять можно: команды их сохраняют.

| Поле | Обязательно | Что это |
|---|---|---|
| `schema_version` | да | `1` |
| `id` | да | имя файла без `.md`; не меняется |
| `title` | да | утверждение: что неверно и к чему ведёт — не тема. Совпадает с `# H1` тела |
| `date` | да | `YYYY-MM-DD`, когда записано |
| `updated` | нет | `YYYY-MM-DD` последнего обновления; ставит `fn.sh touch` |
| `area` | да | инструмент / область, свободной строкой: `git bash / время`, `GitHub Actions / push` |
| `status` | да | `active`, `workaround`, `needs-verification`, `fixed-upstream`, `obsolete`, `promoted` |
| `summary` | да | одна плотная строка для индекса и поиска: механизм, цифры, признак узнавания |
| `tool_version` | нет | версия инструмента, на которой проявилось (`"Codex CLI 0.152.1"`) — попадает в черновик issue |
| `upstream` | нет | ссылка на issue/PR у автора инструмента; обязательна при `fixed-upstream` |
| `candidate_skill` | нет | имя скилла, если заметка может им стать или стала, плюс условие свободным текстом |
| `tags` | нет | слова для поиска, которых нет в заголовке: синонимы, английские названия |

Пустые необязательные поля можно оставить `""` или удалить — `touch` при сохранении их убирает.

## Разделы тела

`# <title>`, затем: `## Контекст` · `## Симптом` · `## Root cause` · `## Фикс / workaround` ·
`## Как проверить` · `## Что увело не туда` · `## Caveats` · `## Критерий превращения в скилл`.
Повторные случаи — `## Обновление DD.MM: <что нового>` в конце. Пустой раздел — убрать.
`issue-draft` ищет разделы по началу названия (`Симптом`/`Symptom`, `Root cause`/`Причина`,
`Как проверить`/`Как воспроизвести`, `Фикс`/`Workaround`/`Обход`), так что английские тоже годятся.

## Индекс

`INDEX.md` собирает `fn.sh index`: новые сверху, одна строка на заметку, колонки
`Date | Note | Area | Status | Upstream | Candidate skill | Summary`; у обновлённых —
`YYYY-MM-DD · обн. MM-DD`. Всё над маркером `<!-- fieldnotes:index … -->` — ручное и сохраняется.
`lint` считает устаревший индекс ошибкой.

## Что проверяет lint

Ошибки: нет или битый frontmatter (в том числе незакрытая кавычка или скобка списка), нет
обязательного поля, неподдерживаемая `schema_version`, неизвестный статус, `id` ≠ имя файла, дата
не строго `YYYY-MM-DD` (`20260101` и `2026-W01-1` — ошибка), `updated` раньше `date`, `fixed-upstream`
без `upstream`, похожее на секрет (ключи `sk-`, `sk_live_`, `gh*_`, `github_pat_`, `glpat-`, `xox*`,
AWS, Google API, токен бота Telegram, Bearer, JWT, приватный ключ), устаревший индекс.
Предупреждения: заглушки шаблона, H1 ≠ `title`, пустой раздел, `needs-verification` дольше 30 дней,
битая относительная ссылка, один slug у двух заметок, имя файла не по образцу.

## Переход со старого формата (1.x)

Старая заметка: `# Заголовок`, под ним строка `- **Date:** … · **Area:** … · **Status:** …`;
индекс вели руками. `fn.sh migrate --from <хранилище>` (без `--apply` — пробный прогон):

- `title` — из H1; `area` — строка Area целиком; `summary` и `candidate_skill` — из строки индекса;
- статусы: `fixed locally` → `workaround`, `promoted to skill (…)` → `promoted` (имя скилла из
  скобок — в `candidate_skill`, если колонка пустая), `deferred` → `active`;
- `updated` — самая поздняя из дат «обн. MM-DD» в индексе, «Обновлено/дополнения …» в строке
  метаданных и заголовков `## Обновление DD.MM`;
- строка метаданных удаляется, остальное тело не трогается; ручная шапка индекса сохраняется
  (без заголовка «## Индекс» над таблицей и без старой таблицы);
- заметки уже в новом формате пропускаются, с битым frontmatter — не переписываются.

Хранилище — не git: перед `--apply` сделай копию.
